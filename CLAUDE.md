# dither

An image host: axum, askama, Datastar and Tailwind, with images in an S3 bucket and state in SQLite. It ships as the image `ghcr.io/radiosilence/dither` and the Pulumi component `@radiosilence/dither-pulumi` in `deploy/pulumi`, which share one version; jaritanet deploys it by pinning that package. The README is authoritative on behaviour.

## Rules that hold the design together

- Nothing an upload carries reaches the store without passing through `sanitize::clean` (in `media::process`, which reads the cleaned bytes back to prove they decode) or, for a video, ffmpeg's remux without metadata (`video::Tools::remux`). Only a worker (`worker.rs`) makes copies, which the web process stores as sent, so the worker API's token is what stands between the store and anyone else; the web process decodes nothing. Every ffmpeg run goes through `Tools::run` with `Tools::input`'s limits and a `sandbox::Sandbox` naming what it reads and where it writes; the sandbox is applied between fork and exec, so `Prepared::apply` makes system calls only (no allocation, no locks). A remux strips SEI from H.264 and HEVC (`sei_filter`, then `mp4::strip_sei` for an HEVC decoder configuration).
- The database is the queue: a job is an image row in state `processing`, claimed with a lease. Only the web process opens the database and holds the store's keys; workers, which may run on other machines, reach the queue through the worker API (`web::work`, `jobs::Hub`), and the store only at URLs it signs for one job's upload and copies, which are placed only while the job is still that worker's. Whatever a request misses, the rows still say what is waiting, made or failed.
- Every database write that a person can cause takes the owner and checks it in the same statement. Handlers never check ownership themselves and then write.
- Routes behind sign-in go in the `protected` router in `web/mod.rs`, behind `require_writer`, which refuses a readonly account's writes; `/account` (`web/account.rs`) is outside it, since its own password is a readonly account's one write, and the admins' routes go in `web/users.rs`'s router, behind `require_admin`. Public routes take no session and must work on the public domain, which has no cookies. The exception is `/albums/{id}`: app-host only, it reads the session itself, since its address is what people copy, and sends anyone but the owner to the album's public page.
- Accounts, sessions, passwords and invites are koan-auth's (`crates/koan-auth` in kōan), over its tables, which `koan_auth::schema::migrate` keeps after dither's own migrations. An album's owner is its account's username, a foreign key to those tables, so an account is deleted only through `Db::delete_account`, which deletes its albums the way `delete_album` does and records their copies as strays. The sign-in pages take forms, not the app's marked writes, so each checks `koan_auth::web::same_origin` and counts against `sign_ins`.
- The public pages carry no script but the video player's (`browser/player.ts`), loaded only on a page with a video. Image files are served with `CSP: default-src 'none'; sandbox`; video files are not sandboxed (a sandboxed document's opaque origin defeats `'self'`, and Safari's own player then never loads) and allow `media-src 'self'` and inline styles, for the player a browser makes of one opened on its own.
- Store keys are built by `store::key` from ids checked by `id::valid`; nothing a client sends becomes part of a path otherwise.

## Git

- Work in PRs; PRs are squashed; merge main into a branch rather than rebasing.
- Releases go through `just release`, never a hand-edited version on main. Never push tags; CI tags and publishes when a release PR merges.
- Commits are signed.

## Changelog

`CHANGELOG.md` is generated by `scripts/changelog.py` and never edited by hand. Every change adds one fragment under `changelog.d/unreleased/<section>/`, named `<pr>-<slug>.md` and holding one `- **Lead.** Detail.` entry. The format is in `changelog.d/README.md`.

## Releasing

`just release patch|minor|major` (or an exact `X.Y.Z`) branches from main, bumps `Cargo.toml` and `Cargo.lock`, `deploy/pulumi/package.json` and its lockfile, and `APP_VERSION` in `deploy/pulumi/src/versions.ts`, turns the unreleased fragments into the version and opens the release PR. Merging it is the release: CI pushes the image's semver tags, publishes the Pulumi package, then creates the GitHub release. `gh workflow run ci-cd.yml` on main retries a release that failed part way. The Release workflow (`gh workflow run release.yml`) needs a `RELEASE_TOKEN` secret, since a pull request opened with the workflow token runs no CI.

## CI/CD

`.github/workflows/ci-cd.yml` is one pipeline, the same shape as slsk-mcp's and tubele's. CI ends in `Checks`, the only status a ruleset should require; CD runs after it on main. The `changes` job decides from the diff which domains a change touches (`rust`, `web`, `package`, `docker`, `deps`), as allowlists of paths: a new top-level directory of code needs adding to its domain. The static musl binaries are built once per architecture and the `scratch` image only copies them in.

## Check

```sh
just check   # Cargo.lock clean, fmt, clippy -D warnings, tests, the Pulumi package, stylesheet fresh, the script's types, changelog, versions
just css     # after changing styles/, a template, class strings in src/ or the kit's version in Cargo.lock
```

## Frontend

- Tailwind v4, standalone CLI from mise, with koan-kit-web's stylesheet imported from the crate's source: `just kit` links it as `styles/kit` (gitignored), so the stylesheet and the components' markup come from the one release `Cargo.lock` names. The typeface is the crate's too (`koan_kit_web::font::serve`). Class names written in Rust or `browser/*.ts` must be literal strings so Tailwind's `@source` finds them.
- The CSP has no `unsafe-inline`: no `style=""` and no inline scripts. The script may set styles through the CSSOM (`el.style`, `el.animate`), which the CSP allows. The headers are askama_datastar's `SecurityHeaders` with the app's `Csp` (`web::app_policy`); a public page or a file sets its own, stricter policy, which the layer keeps.
- The script is TypeScript, typechecked by `just js` and stripped by `build.rs` (oxc) into what the binary embeds. Keep it erasable syntax only (no enums, namespaces or parameter properties), which `erasableSyntaxOnly` enforces.
- Every word a page or the script shows is a gettext message in a template (`__`, `__p` for a context, `__n` for plurals), never a string in Rust or the script. The script reads its words from the layout's `<template id="copy">` by key, a counted line once per plural form (`data-n`). `just i18n` after changing a template's words.
- Two things stay as they are until there is a second language: the API's error text, which the uploader shows as the server words it, since an API's answers serve any client; and numbers, sizes and times, formatted the same way by `web::human` and the script's `human` and `span`, not for a locale.
- Template structs get the gettext vocabulary from `i18n::translated!`; a new template struct goes in its list or its words fail to compile.
- Templates call helpers as methods (`{{ css_url() }}`): askama makes a call in a template a method on the template, which `web::Helpers` supplies to every one.
- The look is kōan's (radiosilence/koan, `docs/design/koan-theme.md`): square, flat, Geist Mono, the app's own words lowercase. Icons are the kit's (`kit::icon::COPY.svg(13)`), the player's included.
- koan-kit-web's components write the markup (`use koan_kit_web as kit;` in a template's module): `kit::Head`, `SkipLink` and `Release` round a page, `Button` (`post`/`get` for a request, busy while it runs; `toggles` for the player's play, mute and full screen), `Form` and `Field`, `Check` (the move dialog's rows, with a picture), `Notice`, `Empty`, `Meter`, `Spinner`, `Pairs` (`optional`, and rows from loops in a `wrap` block), `CopyField` (with a `name`), `Sheet`, and the layout's one `Confirm` and `Flash` region. Use a component before writing markup, and the kit's classes before writing a rule; `styles/app.css` keeps only what is dither's own, and never restyles a kit component's padding, type or height. A control in a row or a toolbar is compact: `.compact()`, or a `compact` class on its container. Every wait is the kit's ensō: a `Spinner`, a busy `Status` or a busy button, never a loader of the app's own. A fragment a template splices in is an `askama_datastar::Html`, which askama writes as it is; no `|safe`. Use the type roles (`fine`, `meta`, `control`, `body`, `title-sm`, `title`, `display`) rather than Tailwind's sizes. `just kit-check` checks the templates, `src` and `browser`; a deliberate exception carries `kit: raw` and its reason.
- A change asked about first is `Button::post(url).confirm(question, yes)`, asked in the page's `Confirm`. Its handler answers `kit::Confirm::close()` once the change is made, `kit::Confirm::go(path)` when the change removed the page, or `kit::Confirm::error` with a template's markup (`app/failed.html`, `app/refused.html`). The button that asked hears `kit-confirmed` once the sheet closes, for the script to follow. What it acts on travels in its address, since the button posts the page's signals rather than a form. The script raises a flash with a `kit-flash` event on `window`.
- A kit prop takes a template's `__()`, `__p()` or `__n()` as it is: those give `i18n::Words`, which convert into the kit's text.
